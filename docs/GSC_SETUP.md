# Google Search Console 网页接入

GSC 使用 [官方网页](https://search.google.com/search-console)。AI 在用户授权的浏览器会话中操作，GSC 不需要 GitHub Secret。首次设置或登录并不代表某个站点已经验证，也不代表已获准操作所有站点。

## 1 安全登录并核实身份

1. AI 说明使用的是哪一台电脑、哪个浏览器，先检查 GSC 当前登录状态。
2. 若未登录、会话过期或需要额外验证，使用当前工具支持的安全登录或用户接管方式，由用户本人在 Google 官方界面完成凭据输入、二次验证和安全挑战。不要把密码、恢复代码或浏览器会话数据发到聊天、仓库或日志。
3. 登录后核对显示的 Google 账号，以及将操作的 property。多个账号或同名站点时先确认，不能只凭浏览器已经打开页面推定身份正确。
4. 仅复用当前有效且已授权的会话；Google 可能要求重新登录，不承诺永久有效。不得关闭二次验证、绕过风控，或更换 IP、账号、会话规避限制。若官方拒绝当前浏览器且无法正常继续，报告具体阻塞，等待支持的正常登录方式。
5. 本指南不自动授予新站点的所有权或第三方持续访问。需要新增权限时，先明确目标、接收权限的身份和影响，并取得相应确认。

## 2 确认目标 property 和本次操作

- 先在 property 选择器中查找已有站点，核对完整域名、协议及主机范围。
- Domain property 覆盖该域名的协议和子域变体；URL-prefix property 按其指定前缀匹配。不要把相似域名或 www 与根域的不同属性选错。
- 明确本次授权是否包括站点验证、指定 sitemap 提交、哪些 URL 的检查或请求索引；只在批准范围内执行。
- 用户的 Google 账号继续保有所需所有者身份，已有验证记录和必要所有者应保留。查看或操作权限不足时，先报告缺少什么，不移除他人或自行扩大授权。

[Google 所有者与权限说明](https://support.google.com/webmasters/answer/7687615?hl=en)

## 3 在网页验证站点

1. 已验证且正确的 property 直接复用；新增内页无需重新验证整站。
2. 需要新建 Domain property 时，在用户确认的账号下添加准确域名，从当前验证页获取 Google 实际给出的 DNS TXT 名称与值，不使用示例值。
3. 核对当前权威 DNS。若已由 Cloudflare 托管，可在获得指定 zone 和记录变更授权后，用 Cloudflare API 添加该 TXT；不要覆盖其他 TXT、邮件记录或旧的有效验证记录。
4. 核对记录已对外发布并等待传播，然后回到 GSC 官方网页点击“验证”。验证失败时记录实际原因并检查传播，不反复创建重复记录。
5. 以网页明确显示验证成功为准，并核实用户账号的所有者身份。成功后继续保留验证记录。

[Google 网站所有权验证指南](https://support.google.com/webmasters/answer/9008080?hl=en)

## 4 提交 sitemap 并检查 URL

1. 核对正式 sitemap 的完整 HTTPS 地址，确认可访问且内容使用正确正式域名。
2. 在正确 property 的“Sitemap”页面提交用户批准的地址，之后读取处理状态与错误。提交成功、等待处理和已成功读取是不同状态。
3. 用顶部 URL 检查工具查看首页及指定重点内页。默认结果可能来自 Google 已保存的索引版本。
4. 需要当前可抓取情况时，在官方页面功能和权限允许的情况下使用“测试实际网址”。实时测试结果不等于已收录。
5. 经授权且页面提供“请求编入索引”时，对指定 URL 操作一次并记录结果。遵守配额与等待状态；重复提交不保证更快处理，不切换账号或会话规避限制。
6. 新站没有搜索数据、网址尚未收录或 sitemap 等待处理可能是正常状态。不要把登录成功或按钮点击成功写成网站已收录。

[Google Sitemap 报告](https://support.google.com/webmasters/answer/7451001?hl=en) · [Google URL 检查与请求索引](https://support.google.com/webmasters/answer/9012289?hl=en)

## 5 交付记录

只记录已核实的 Google 身份、目标 property、站点验证状态、sitemap 地址及处理结果、指定 URL 的索引/实时测试/请求结果，以及等待项或阻塞。保留能够安全打开的官方页面链接，不记录凭据、验证码或会话数据。

当前仓库的 `Verify API credentials (read-only)` 仅测试 Cloudflare 与 Spaceship。它的成功不代表 GSC 已登录、已验证或已提交；这些以实际网页结果为准。
